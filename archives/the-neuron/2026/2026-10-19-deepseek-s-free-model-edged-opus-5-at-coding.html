DeepSeek's Downloadable Model Edged Out Opus 5 on a Coding Test, and Its Web Search Undercuts Rivals by 85%

On Saturday, DeepSeek released two things at once: a model update called V4.1-Flash-1017, and public access to its own web Search and Fetch tools for AI agents. Think of it as a new brain plus a pair of eyes, both priced like a clearance sale.

The brain first. This is a minor update to DeepSeek's cheaper "Flash" tier, and the weights are free to download under an MIT license, so anyone can run it or build a paid service on it. On DeepSWE v1.1, a coding-agent test, DeepSeek reports 77.0, versus 74.0 for Claude Opus 5 and 73.0 for GPT-5.6 Sol.

The fine print: DeepSeek ran those tests itself, and Opus 5 still wins on Humanity's Last Exam (56.3 to 42.6) and Terminal-Bench 4.0 (51.8 to 42.3). Read it as a great-value coder, not a new smartest model.

The value part is real, though. DeepSeek charges $0.15 per million input tokens (word-sized chunks of text) and $0.60 per million output tokens off-peak. In August, Artificial Analysis found the earlier Flash model cost about 3 cents to run its whole test suite, versus $1.86 for GPT-5.6 Sol and $3.15 for Claude Fable 5. Three cents. A single sticky note costs more.

Now the eyes. An AI model can't browse the web by itself, so it needs tools. DeepSeek's Search and Fetch are two: Search returns ranked results for a query, and Fetch opens one page and returns its text as Markdown (plain text with light formatting). The pricing:

  • Each costs $0.75 per 1,000 successful requests. Failed and empty calls are free.

  • One pricing roundup lists rivals at $5 per 1,000 and up, including Brave, Tavily, and Perplexity. That's the 85% gap in the headline.

  • Calls made through DeepSeek Harness, Claude Code, or Codex are free until billing starts November 1, Beijing time.

Pages come back as full text, which is exactly the big-tool-output problem in today's AI Skill below.

So what does this do to everyone else? Our read: open weights cap prices, since any cloud can host the model and OpenRouter already lists about a dozen. Analysts cited by IBTimes see that as a structural challenge to closed labs' premium pricing. The top models look safe on the hardest reasoning, so the squeeze lands on bulk work like routine coding and agent loops. No rival has cut prices yet, so that's a forecast.

Then there's the geopolitics, because DeepSeek never launches in a vacuum:

  • Copying accusations: On September 8, the NSA, FBI, and CISA issued a joint advisory saying DeepSeek and Alibaba used distillation at industrial scale. That means training a model on another model's answers, like copying a straight-A student's homework. Beijing has pushed back and hinted at retaliation.

  • The chip fight: IDC says Nvidia's share of China's AI chip market fell to 34% in early 2026, while Huawei's rose to 28%.

  • Beijing's own brakes: On Friday, China proposed export controls on 23 AI items, including weights for models with 2 trillion or more parameters or a top-10 world ranking. The draft names no models, but Bloomberg and the AP say Kimi K3 and Qwen3.8-Max exceed the size line. API and app access would continue.

Notice what DeepSeek shipped on the safe side of that line: open weights for a mid-size model, and a pay-per-call API for the rest. Strategy or coincidence? We can't tell.

What this means for you: Search and Fetch run on DeepSeek's servers, and several governments restrict DeepSeek on official devices over data security. Public-web research is a reasonable use. Keep confidential material out, and check your IT policy first.

Two dates to watch: November 1, when the free window ends and real bills begin, and whether anyone independent can reproduce that 77.0.

🎓 AI Skill of the Day: Stop Your AI Agent From Drowning in Its Own Tool Output

Picture an agent that watches your app's logs. Every check, the tool dumps another big batch of log text into the conversation, and the agent re-reads all of it on every turn. AWS developer advocate Elizabeth Fuentes Leone walked through this in a talk posted October 7. Agents break when tools return big outputs, and a bigger context window (how much text a model can hold in view at once) doesn't fix it.

In her session abstract, one tool returned 214KB of logs, the answers got worse, and nothing threw an error.

How bad does it get? Chew Loong Nian re-ran her fixes in AWS's open-source Strands agent framework with a scripted model.

Eight log fetches left a default agent holding about 252,000 tokens of history (tokens are the word-sized chunks a model counts). One built-in plugin cut that to about 9,000. The obvious shortcut, a smaller sliding window, cut it to about a quarter of that, but it throws away whole turns, including whatever the agent learned from them.

The plugin uses a memory pointer: the big output goes into storage, and the agent's context gets a short ID it can use to fetch the data later.

Her second fix is a cap on repeat calls. In her abstract, an agent that retried the same call fourteen times dropped to two once it had a clear "done" signal and repeat calls were blocked. Fourteen to two. Somebody's API bill just exhaled. One caveat: Chew's test measures how much text stays in context, not whether the answers improved.

You probably aren't writing Strands code, but her abstract says the fixes work with any agent framework. If you build or buy agents, ask for three things:

  1. Store big tool outputs outside the conversation and hand the agent a short ID.

  2. Cap how many times an agent can call the same tool per task.

  3. Give the agent a clear "done" signal. 

Review my agent for tools that can return large outputs (logs, search results, files). For each one: (1) save the full output to a file and return only a short summary plus a file ID, (2) set a maximum number of calls per tool per task, and (3) add a clear "done" condition so the agent stops once it has an answer.
